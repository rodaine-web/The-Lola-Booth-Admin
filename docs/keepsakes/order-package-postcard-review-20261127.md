# Staging: packed orders and postcard approval

In-house checkout estimates now combine product profiles into one parcel per order/delivery destination. Before requesting its shipping label, Admin confirms the actual packed box dimensions and total weight. Product profile capacity estimates layers rather than creating separate labels. Saving the packed box preserves the shipping amount already paid and archives only unused quotes or voided/error rows. Purchased, dispatched and delivered label history cannot be consolidated. Multiple requested delivery destinations remain separate rather than silently redirecting a recipient.

New Lob jobs prepare purchased artwork and wait for explicit Admin approval. The Integration section shows private front/back proofs, print guides, recipient and return addresses, replacement uploads and full-resolution downloads. Uploads invalidate approval. Checks normalize exact 1875 × 1275 PNG files at 300 DPI, require the mailing area to stay white and preserve the standard Lola Connect QR. The combined upload budget is 4.8 MB. Staff confirms safe-area content and absence of crop/postage marks. The worker sends the exact approved checksums using a stable revision-specific idempotency key. Uncertain outcomes lock replacements pending reconciliation; confirmed provider rejection permits the same approved submission to retry.

Submitted postcards expose provider status and a read-only refresh action. Refresh reconciles the existing provider ID, clears resolved item errors and recomputes order status without submitting another copy. Submitted artwork is locked. New unsent files remain editable. Original Gallery assets are preserved.

The existing six-line staging test order has four already delivered test labels and one Lob postcard in rendered/submitted status. Preserve these historical records; do not void labels or resubmit the postcard to demonstrate consolidation. New/unshipped orders use the single-package flow.

Validation: 72 local commerce, database and browser tests passed; build passed. Desktop/mobile review covers both-side proofs, replacement, stale-approval rejection, safe mailing area, exact approved bytes, no preapproval dispatch, status refresh without resubmission, single shared label, legacy unused-quote consolidation, unchanged customer shipping and carrier handoff before delivery completion. No real payment, customer notification or production deployment was performed.

Automated checks do not judge arbitrary artwork content; the Admin visual confirmation remains required.
