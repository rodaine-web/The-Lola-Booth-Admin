# Staging: event photo delivery from Campaigns

Open Communications → Campaigns → Event photo delivery, or `/communications/campaigns?mode=event-photos`. Select an accessible event, import its original Fiesta sharing CSV/XLSX if needed, choose email/SMS and review matched collections. Import preserves the original filename/contact mapping and does not publish Galleries or send messages. CSV is bounded to 1 MB; XLSX is bounded to 2 MB, 5,000 source rows, 66 Fiesta columns and 8 MB expanded XML. Formula cells and external content fetching are unsupported. The existing strict Fiesta event-code and matching rules remain in force.

Collection eligibility reuses existing Gallery authorization, active person/key, publication, retention and image assignment checks. Missing photos are counted separately and do not produce empty links. Admin can record reviewed transactional delivery permission for selected channels with explicit confirmation and audit evidence. Previous authorization revocations and SMS opt-outs remain excluded. Photo delivery does not create marketing subscriptions or verified phone/email identity records.

The review groups all eligible image assignments by normalized contact within the selected event, showing image counts, existing delivery history and SMS segments/cost. Separate email and phone records are not assumed to represent the same person. Each selected channel delivers at most once per event/contact using the same unique Gallery delivery ledger as publication notifications. Prior attempts are excluded, including uncertain outcomes; opening or approving another review does not resend. Recipient/photo/permission/history changes invalidate approval. Reviewed budgets are rechecked and reserved atomically.

Email contains one expiring collection link, not an email per image. SMS retains the existing token-scoped phone-access flow; it never establishes permanent phone ownership. Download/share/Keepsakes flows remain attached to the guest collection. Existing STOP handling, callbacks, cost reconciliation and worker authorization checks are reused. Event campaigns have a separate review/history record from marketing campaigns.

Staging SMS remains simulated regardless of flags. Staging email approval rejects recipients outside the explicit test inbox policy, and the worker checks that policy again. No live SMS transport was enabled, no Galleries were republished and no customer emails were sent for this implementation. Hosted staging readiness at inspection: all five Twilio credential entries absent, Gallery SMS disabled, generic SMS provider `none`, sender registration and live enable flags false. Configuring credentials alone will not authorize production SMS.

Validation includes synthetic CSV/XLSX mapping, multi-image single collection redemption, event isolation for the same contact at another event, permission/opt-out checks, revoked access, changed review rejection, repeated approval and duplicate campaign prevention, staging recipient blocking, existing 400-recipient budget/concurrency/webhook regressions and desktop/mobile confirmation flow.
