# Independent Keepsakes order processing — staging

One customer order has three independently processed sections: Digital orders, Fulfilled in-house, and Fulfilled by integration. The pending queues reflect each section's jobs rather than the overall order label. Needs attention opens the affected processing section. Each section shows its own progress inside the same order; existing new-paid-order Admin notifications link there.

Digital work shows authenticated source previews and downloads. Staff select the edited file, explicitly confirm its quality/delivery, and upload it. Files are normalized to JPEG. Completion sends a durable, deduplicated email linking to secure expiring downloads; it does not wait for physical/provider work. Digital-only checkout on both shop surfaces requires email without a delivery-address form. Stripe Checkout collects any tax-location details securely and calculates tax there; the signed payment webhook verifies subtotal, completed automatic tax, tax amount and total before granting fulfillment. Existing physical/postcard address requirements remain. Staging Stripe Tax settings and an active test registration were checked without changing account configuration.

In-house confirmation, packing and order-level package labels remain together. Provider errors do not hide healthy in-house artwork or actions. A payment-time inventory shortage marks only the affected in-house jobs for stock review; digital/provider work is still created. Stock recovery rechecks and reserves available inventory before preparation. Artwork, stock and shared-package readiness checks remain required. Financial/payment holds still apply to all fulfillment.

Integration items show their provider status, recipient/copy context, saved artwork, specific error and item-only retry action. Submitted or ambiguous provider requests retain reconciliation/idempotency safeguards. WHCC/Gelato products remain coming soon while their verified purchasing integrations are incomplete. The failing postcard's oversized photo PNG is re-encoded with lossless adaptive filtering at the same print dimensions. The upload budget is retained; no cropping, resampling or image-quality reduction is introduced by the fix.

Customer shipment/delivery milestones cover in-house items independently; provider submission/delivery and digital readiness have separate item notices. Messages identify the affected items and keep secure named hyperlinks. Staging remains restricted to approved test inboxes; no SMS or marketing consent changes occur.

Cancellation/refund controls offer the whole remaining order or selected item quantities. A server-generated preview identifies quantities, product amount, exact allocated tax, shipping treatment and final refund amount before explicit confirmation. Selected-item refunds exclude shipping; whole-order refunds include the remaining paid total. Durable adjustment records, stable Stripe idempotency keys and signed refund reconciliation prevent repeated clicks or a lost response from generating duplicate refunds. Unknown outcomes block new requests and require reconciliation of the existing request. Unaffected quantities, artwork, downloads and fulfillment remain available. Purchased quantities/recipient encryption are preserved; cancelled quantities and refund history are displayed separately. Unproduced reserved inventory is returned when appropriate.

Partial tax allocation uses original Stripe transaction line amounts/taxes, including cumulative cent rounding across quantity refunds; reversals run separately with durable per-adjustment progress. If the original allocation or remaining shipping tax cannot be verified, the preview stops with an accounting-review explanation. Submitted/ambiguous supplier work and existing postage require provider/label review before cancellation/refund. Unpaid checkouts are cancelled as a whole rather than modifying an already issued payment page.

Validation covers desktop/mobile mixed-order processing while a postcard remains blocked, source download and confirmed edited upload, one shared package label, targeted provider recovery, email-only cart checkout, explicit refund previews, role checks, selected-unit quantities, exact partial tax, duplicate/lost-response refunds, independent item emails, stock-race recovery, encrypted recipient storage and closed-order holds. Tests use intercepted provider calls and disposable local QA schemas. The affected customer order is inspected read-only; no production promotion or customer-order advancement is part of this release.
