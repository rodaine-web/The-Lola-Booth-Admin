# V1.1 controlled production release

Release scope: agreements and event-scoped client workspace; campaign offers in proposals; interest → FOLLOW_UP lead → deposit invoice → confirmed-payment client/event conversion; campaign tracking and lifecycle; dashboard Today correction; persisted business contact settings.

## Before promotion

- Require passing staging validation: unit suite, complete migrations on disposable PostgreSQL, real API lifecycle/permissions, browser journey and build.
- Confirm the staging frontend, API and worker use the same approved commit.
- Verify a current production backup and record the existing production deployment revision.
- Review production settings and origins without copying staging secrets or database records. Production QA/demo contacts, events, invoices, signatures and payments must not be imported.
- Verify the business contact email and phone. The Settings UI now displays the persisted email; previously it hid the legacy address behind an unsaved replacement. Existing issued proposal snapshots remain unchanged. Regenerate corrected drafts explicitly.
- Keep production email behavior live and staging recipient restrictions isolated. Check approved sender aliases and tracking/public document origins.

## Deployment sequence

1. Review the main-staging → main promotion diff, preserving production Vercel routing/hosting changes.
2. Apply all pending migrations through 045 using the existing migration runner against the verified production database. Do not seed or import demo data. API startup already runs migrations.
3. Deploy API and worker, then the frontend for the same release revision.
4. Set V11_CLIENT_WORKFLOW_ENABLED=true on the production API only after migrations and health checks succeed. Default is false; contracts/workspaces remain unavailable in production without the explicit flag. Other permissions, token expiry/revocation, signed immutability and environment email protections remain enforced.
5. Smoke-check owner login, one authorized demo document, public proposal/PDF, agreement access, invoice display, campaign interest and worker processing. Confirm external email inbox delivery separately.

## Conditions / deferred integrations

Gallery storage and real upload/download delivery, Meta, Google and other unconnected providers are deferred to October 6, 2026. Keep them disabled/unavailable until connected and verified. Live Stripe/PayPal checkout is not certified by synthetic/manual-payment tests; use verified offline recording only unless provider UAT is completed. Estimated opens and tracked clicks do not establish email delivery.

## Rollback

Disable V11_CLIENT_WORKFLOW_ENABLED to stop new production agreement/workspace access. Preserve signed records and migration history. Roll back application deployments only after checking compatibility with nullable campaign payment customer references and the expanded invoice context. Do not drop new tables or remove customer financial records as rollback. Pause affected campaign/reminder workers if processing is faulty, and reconcile uncertain sends before retrying.

This preflight prepares promotion; it does not authorize or claim a production deployment or certify deferred integrations.
