LOLA ADMIN — PRODUCT STABILIZATION + OPERATIONS DASHBOARD REDESIGN

IMPORTANT PRODUCT DECISION

LOLA Admin is NOT production-ready.

DO NOT deploy this Admin/API/worker to production during this sprint.

DO NOT create a staging environment yet.

We will continue developing and testing locally/current development environment until
the Admin reaches an acceptable product-quality baseline.

Only AFTER this sprint is completed, thoroughly tested, visually approved, and the
business workflows work end-to-end will we create an isolated staging environment.

The public website v1 remains separate/frozen for now unless specifically required for
local/API contract testing.

PAYMENTS ARE OUT OF SCOPE.

Do NOT:
- enable Stripe
- execute payments
- test live payments
- change payment-provider architecture
- enable SMS
- deploy incomplete Admin changes to production

==================================================
CURRENT AUDIT BASELINE
==================================================

Use the September 24 Admin audit as the defect baseline.

Known results:

- 159 automated tests passed
- production client build passed
- 16 disposable DB integration groups passed
- all migrations through 023 are present/applied in audited environment
- core CRM/document/access-control foundation exists

BUT the Admin is NOT operationally ready.

Confirmed major problems include:

1. Communications module is broken.
2. Date-only values shift backward by one day.
3. Currency/decimal formatting is inconsistent.
4. Raw IDs appear throughout the UI.
5. Proposal/invoice legacy records have inconsistent identifiers/data.
6. CMS source-of-truth migration is incomplete.
7. Equipment UI is incomplete.
8. Staff UI is incomplete.
9. Files UI is incomplete.
10. Client Galleries UI is incomplete.
11. Dashboard/Analytics use contaminated QA/seed data and inconsistent formatting.
12. Integration cards disagree with actual system health.
13. Settings contain inconsistent business information.
14. Some controls visually exist but do nothing.
15. Navigation has excessive/redundant complexity.
16. Mobile Dashboard is too long.
17. Live Operations board overflows horizontally.
18. Audit Log is too technical/raw.
19. Calendar selectors expose raw IDs.
20. Tasks expose raw user IDs.
21. Proposal and invoice records require data consistency work.

We are fixing PRODUCT QUALITY, not increasing feature count.
